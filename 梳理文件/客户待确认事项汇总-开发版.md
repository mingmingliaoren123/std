# STA-100 客户需求事项汇总与待确认清单

## 1. 使用说明

本文件根据以下材料整理：

- 客户与 OpenClaw 的沟通记录；
- 现有 `cycling-agent` 项目；
- 客户已答复的 [需求澄清问题.md](/home/User/gsx/gitdir/std/需求澄清问题.md)。

本文件只面向客户需求和业务决策，不讨论模型、编程语言、部署方式、接口实现等技术方案。技术方案由开发团队在后续设计阶段单独确认。

客户已答复的事项已归入“已确认需求”，不再重复提问。“待确认事项”仅保留当前材料中无法明确判断、且会影响产品内容、业务数据、页面文案或验收结果的事项。

## 2. 已确认需求

### 2.1 产品定位

| 事项 | 已确认需求 |
|---|---|
| 核心产品 | `STA-100` 私有智能体设备 |
| 市场目标 | 进入欧洲 AI 市场，不是只做欧洲自行车市场 |
| 产品定位 | 面向企业客户的生产力工具 |
| 行业定位 | 骑行行业是第一个行业样板，不是唯一应用场景 |
| 后续方向 | 需要扩展到更多行业和更多公司客户 |

### 2.2 页面与使用体验

| 事项 | 已确认需求 |
|---|---|
| 页面范围 | 保留全部现有页面 |
| 页面入口 | 保留控制台、搜索、行业看板、全量看板、产品页、客户使用页、安装页等现有入口 |
| 现有功能 | 保留全部现有功能 |
| 未完成能力 | 现有未实现、演示、占位能力需要补成可用功能 |
| 交互方式 | 保留现有侧边栏、导航、搜索、推荐、订阅、线索、工具、多语言等交互 |
| 视觉要求 | 保持现有页面结构和风格；允许在不破坏结构的前提下微调 |

### 2.3 功能范围

| 事项 | 已确认需求 |
|---|---|
| 智能体能力 | 全部保留并可用 |
| 客户能力 | 客户搜索、客户开发、客户跟进、客户风险等全部实现 |
| 业务工具 | OEM 匹配、报价、物流、付款、合规、单据等全部实现 |
| 内容能力 | 日报、周报、推荐、知识检索、行业内容等全部实现 |
| 行业模块 | 现有设计、维修、市场、品牌、库存、发票、B2B、二手交易、尺码、兼容等模块全部实现 |
| 自动任务 | 新闻采集、视频采集、翻译处理、价格快照、日报、周报、推荐等全部保留 |

### 2.4 数据与历史内容

| 事项 | 已确认需求 |
|---|---|
| 现有数据目录 | 沿用现有数据、客户资料、知识资料、原始采集资料、页面资源等目录 |
| 现有资料 | 保持现有资料结构和内容可继续使用 |
| 数据迁移 | 需要迁移能力 |
| 历史数据 | 可作为测试数据使用 |
| 测试数据 | 支持后台清理 |

### 2.5 用户、多语言与交付

| 事项 | 已确认需求 |
|---|---|
| 用户能力 | 暂时需要登录、权限、多用户和用户隔离 |
| 用户识别 | 保留现有用户和会话识别方式 |
| 多语言 | 保留现有 17/18 种语言能力 |
| 默认语言 | 中文优先 |
| 文案体系 | 保持现有产品命名和词汇体系 |
| 安装体验 | 保留本地静态页面、PWA 和桌面快捷方式体验 |
| 运行结果 | 新系统需要在当前环境中正常运行 |
| 验收目标 | 页面、功能、数据、自动任务和前后端交互均需要正常可用 |

## 3. 仍需客户确认的业务事项

说明：以下内容只保留当前材料里还不能完全确定、且会影响页面展示、业务流程、数据口径或验收结果的事项。若客户在其他文档里已确认，可直接以已确认内容为准。

### 概览页面

#### 日报订阅
1. 概览页和日报订阅页展示的信息来源分别是什么？例如本地资料、本地模型结果、OpenClaw 处理结果、TF 卡中的 Markdown 文件、外部采集内容，还是客户手工维护内容？
2. “最近搜索”是按当前登录用户、当前公司，还是整个系统历史来展示？

### OEM 工厂智能匹配

1. 页面数据展示和智能匹配分别基于哪些数据？例如工厂资料、产品资料、客户需求、历史订单、客户提供的表格或文件。
2. 卡片视图里的“查看详情”需要展示哪些信息？
3. 导出的报告是否要和现有样式保持一致？
4. TOP 排序依据是什么？

### 客户开发

1. 客户开发时主要通过哪些字段进行匹配和筛选？
2. 客户开发是从客户档案、历史订单、外部客户列表，还是私有数据库中进行匹配？
3. 哪些字段是必须参与优先级判断的，哪些只是辅助展示？

### 今日日程

1. 今日日程的数据从哪里来？
2. 这些日程是系统自动汇总、人工维护，还是导入生成？

### 智能体页面

1. 页面上的 24 个智能体，是否每一个都对应一个 OpenClaw agent，还是只是页面上的能力分类？
2. 哪些需要对外展示，哪些只用于内部使用？

### 单据页面

1. 单据是根据哪些数据生成的？
2. 生成的各类单据分别需要什么样的样式？
3. 单据需要保存多久？

### 订单页面

1. 新建订单是否需要按不同平台生成不同的订单草稿？
2. 生成草稿后，是否还需要继续访问对应网站完成真实下单？
3. 订单状态是否需要和外部平台保持关联并同步更新？
4. 如果需要同步外部平台订单状态，客户是否能提供或授权对应平台账号，用于读取订单信息？
5. 订单状态和订单详情需要实时同步，还是按固定时间同步？

### 客户页面

1. 新建客户时，除了公司、类型、国家、联系人、信用评级、中信保额度外，是否还需要补充其他字段？
2. 页面里展示的订单数和总金额，是手工填写，还是从订单数据中自动统计？

### 私有数据库页面

1. 页面里的本地数据是否来自 TF 卡或其他本地存储？
2. 提供的数据是否已经按分类整理好？
3. 新增数据、更新数据、格式转换是否需要区分处理？如果不区分，每次全量处理可能会耗时较长、成本更高。
4. 上传文件后，文件最终要归档到哪里？例如系统私有资料库、TF 卡指定目录、客户指定资料目录，还是其他位置。

### 行业日报页面

1. 本周日程的数据从哪里来？
2. 已完成和未完成是否需要区分展示？
3. 哪些日程需要标记完成，谁来标记？

### 设置页面

1. 微信小程序绑定后，需要推送哪些信息？
2. 需要同步哪些数据到小程序？
3. 绑定后的页面希望长什么样，或者主要能完成哪些功能？
