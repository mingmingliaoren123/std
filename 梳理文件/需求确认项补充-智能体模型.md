## 2. 必须确认的问题

### 2.1 生产智能体是否必须使用真实模型

建议确认：

- Go 版生产环境必须默认使用真实模型。
- `mock` 只能作为开发/演示开关，不能作为默认运行状态。
- `/api/health`、`/api/chat`、`/api/agent/call` 必须返回 `mock_mode=false` 或等价状态字段。

### 2.2 底层模型是否确认为 DeepSeek V4-Flash 7B INT4

建议确认：

- 首期沿用现有项目文案中的 `DeepSeek V4-Flash 7B INT4`。
- 模型路径继续兼容 `models/deepseek-v4-flash-7b-int4/model.gguf`。
- 如后续替换模型，接口和前端展示字段不变，只更新模型配置。

### 2.3 Go 版模型调用方式

需要在以下方案中确认一种：

| 方案 | 说明 | 影响 |
|---|---|---|
| 方案 A：Go 直接集成 llama.cpp | Go 程序通过 CGO/Go binding 直接加载 GGUF | 单进程，但编译、ARM 依赖和性能调优更复杂 |
| 方案 B：Go 调本机 OpenAI-compatible LLM 服务 | Go 后端通过 HTTP 调本机模型服务，例如 llama.cpp server / vLLM 类接口 | 架构更清晰，模型服务可单独升级，但不再是纯单进程 |
| 方案 C：Go 内置接口适配层，首期支持 A 或 B | 统一 `LLMAdapter`，部署时选择直连 GGUF 或本机服务 | 最稳妥，便于后续模型替换 |

建议确认采用：**方案 C**。

### 2.4 模型不存在或加载失败时如何处理

建议确认：

- 生产环境模型加载失败时，`/api/chat` 不允许伪造回答。
- 返回明确错误：`MODEL_NOT_READY`、`model_loaded=false`、`mock_mode=false`。
- 控制台显示模型未就绪，并给出模型路径、缺失文件、修复建议。
- 开发环境可通过配置 `STA100_MOCK_ENABLED=true` 开启 mock。

### 2.5 RAG 与模型的关系

建议确认：

- 智能体回答必须保留 RAG 检索来源。
- 返回字段继续包含：`response`、`sources`、`confidence`、`latency_ms`、`agent`、`agent_name`。
- 需要新增或保留状态字段：`model_name`、`model_loaded`、`rag_available`、`mock_mode`。
- RAG 无命中时，模型可以回答通用建议，但必须标注“未命中本地知识库”。

### 2.6 模型升级和配置

建议确认：

- 支持通过配置切换模型名称、模型路径、上下文长度、线程数。
- 支持 OTA/后台升级模型，但升级包必须做校验。
- 模型文件不应写入 SQLite，应作为独立文件放在 `models/`。

建议环境变量：

```text
STA100_LLM_PROVIDER=llamacpp
STA100_LLM_MODEL_NAME=DeepSeek V4-Flash 7B INT4
STA100_LLM_MODEL_PATH=./models/deepseek-v4-flash-7b-int4/model.gguf
STA100_LLM_SERVER_URL=http://127.0.0.1:8080/v1/chat/completions
STA100_LLM_CONTEXT=4096
STA100_LLM_THREADS=8
STA100_LLM_GPU_LAYERS=0
STA100_MOCK_ENABLED=false
```

## 3. 建议写入正式需求的结论

Go 版智能体底层必须实现为可配置的真实 LLM Adapter：

- 默认目标模型沿用 `DeepSeek V4-Flash 7B INT4`。
- 默认模型文件路径兼容 `models/deepseek-v4-flash-7b-int4/model.gguf`。
- 支持本地 GGUF / llama.cpp 推理链路。
- 不允许生产环境默认 `mock_mode=true`。
- 模型不可用时返回明确错误，不再伪装成真实回答。
- 智能体回答必须结合 RAG，并返回来源、置信度、模型状态和耗时。
